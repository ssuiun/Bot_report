# Корпоративный Telegram-бот «HR / Акты / Финансы»

Бот на **aiogram 3** для учёта статусов сотрудников (в офисе/отошёл), актов передачи
документов/имущества и расходов сотрудников с автоматической выгрузкой всех данных
в **Google Sheets** в реальном времени.

## Возможности

| Модуль | Что делает |
|---|---|
| 📍 Статус | «Ухожу» (куда/зачем/когда вернусь) → карточка в чат + строка в Sheets; «Я вернулся» → обновляет ту же строку; «Кто в офисе» — витрина 🟢/🔴; «Мой профиль» — история перемещений |
| 📄 Акты | Пошаговое создание акта передачи (что/кому/срок/комментарий) → строка в Sheets; «Мои акты» — список открытых, отметка «Возвращено» одним нажатием (обновляет ту же строку) |
| 💰 Финансы | Категория (кнопки) → сумма → описание → фото чека (опционально, пересылается в лог-чат, ссылка на сообщение сохраняется в Sheets) |
| ⚙️ Админ-панель | Добавить сотрудника (`/add_user`), заблокировать доступ, получить ссылку на общую таблицу |

Роли: **admin** (полный доступ + админ-панель) и **employee** (свои функции + просмотр статусов коллег).
Доступ закрытый — работает только с сотрудниками, добавленными в базу данных.

## 1. Установка зависимостей

```bash
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## 2. Создание Telegram-бота

1. Напишите **@BotFather** в Telegram → `/newbot` → следуйте инструкциям.
2. Скопируйте выданный токен — он понадобится в `.env`.
3. (Опционально) командой `/setprivacy` → `Disable` разрешите боту видеть все сообщения
   в групповых чатах, если планируете использовать групповой лог-чат.

## 3. Настройка Google Sheets

1. Зайдите в [Google Cloud Console](https://console.cloud.google.com/) → создайте проект.
2. **APIs & Services → Library** → включите **Google Sheets API** и **Google Drive API**.
3. **APIs & Services → Credentials → Create Credentials → Service Account**.
   Создайте сервисный аккаунт, затем во вкладке **Keys** → **Add Key → JSON** — скачается файл ключа.
4. Переименуйте скачанный файл в `credentials.json` и положите в корень проекта
   (рядом с `main.py`), либо укажите свой путь в `.env` (`GOOGLE_CREDENTIALS_FILE`).
5. Создайте новую таблицу Google Sheets. Откройте её и **share** (Настройки доступа) —
   выдайте права **Редактор** email-адресу сервисного аккаунта
   (выглядит как `xxxxx@your-project.iam.gserviceaccount.com`, указан в `credentials.json`).
6. Скопируйте ID таблицы из её URL:
   `https://docs.google.com/spreadsheets/d/ЭТА_ЧАСТЬ_ЭТО_ID/edit` → вставьте в `.env`
   как `GOOGLE_SHEET_ID`.

Листы `Лист1_Статус`, `Лист2_Акты`, `Лист3_Финансы` бот создаст сам при первом запуске,
если их ещё нет (с заголовками столбцов).

## 3.1. Настройка Google Drive (для фото чеков)

Фото чеков из раздела «Финансы» теперь загружаются в Google Drive, а в таблицу
записывается постоянная ссылка на файл.

1. В обычном (не сервисном) Google-аккаунте создайте папку в Google Drive.
2. Откройте доступ к папке сервисному аккаунту (тот же email из `credentials.json`,
   что и для Sheets) с правами **Редактор**.
3. Скопируйте ID папки из её URL: `https://drive.google.com/drive/folders/ЭТА_ЧАСТЬ`
   и впишите в `.env` как `GOOGLE_DRIVE_FOLDER_ID`.
4. Если `GOOGLE_DRIVE_FOLDER_ID` не задан — файлы будут грузиться в корень диска
   самого сервисного аккаунта (доступ к нему сложнее получить руками, поэтому
   папку лучше настроить).

Если Google Drive недоступен (не настроен, нет прав, нет сети), бот не падает —
он автоматически пересылает фото в `LOG_CHAT_ID` как раньше и сохраняет ссылку на
это сообщение.

## 4. Настройка `.env`

```bash
cp .env.example .env
```

Заполните:
- `BOT_TOKEN` — токен от BotFather.
- `SUPER_ADMIN_IDS` — ваш Telegram ID (узнать: напишите боту `/start` до регистрации,
  он покажет ваш ID; впишите его сюда и перезапустите бота — вы автоматически станете админом).
- `LOG_CHAT_ID` — ID чата/группы/канала, куда дублируются уведомления и чеки
  (можно указать тот же ID, что и `SUPER_ADMIN_IDS`, тогда всё будет приходить вам в личку).
- `GOOGLE_SHEET_ID`, `GOOGLE_CREDENTIALS_FILE` — из шага 3.

## 5. Запуск

```bash
python3 main.py
```

Бот стартует в режиме long polling. Для продакшена рекомендуется запускать через
`systemd`, `pm2` или Docker с автоперезапуском.

## Как добавить сотрудника

1. Сотрудник открывает бота и жмёт **/start** — бот покажет ему его Telegram ID
   (регистрация ещё не пройдена, доступа нет).
2. Сотрудник присылает этот ID администратору любым удобным способом.
3. Администратор в боте: **⚙️ Админ-панель → ➕ Добавить сотрудника** (или команда `/add_user`)
   и по шагам вводит ФИО, должность, телефон, Telegram ID.
4. Бот автоматически пришлёт сотруднику приветственное сообщение (это сработает, только
   если сотрудник уже хотя бы раз писал боту — таковы ограничения Telegram API: бот не может
   первым написать пользователю, который никогда не начинал с ним диалог).

## Важные технические примечания

- **Хранилище FSM** — сейчас `MemoryStorage` (в оперативной памяти). Для работы на нескольких
  процессах/серверах или чтобы не терять состояние диалога при перезапуске бота,
  замените на `RedisStorage` (`aiogram.fsm.storage.redis`).
- **База данных** — SQLite (файл `hr_bot.db`), этого достаточно для одной небольшой компании
  и одного процесса бота. Для более высокой нагрузки/нескольких серверов перейдите на PostgreSQL
  (структура таблиц в `db/database.py` переносится почти без изменений, замените `aiosqlite` на
  `asyncpg` и используйте пул соединений).
- **Google Sheets и лимиты** — Google API имеет квоты (по умолчанию ~60-300 запросов в минуту
  на проект). Для типичной компании из нескольких десятков сотрудников этого более чем достаточно.
- **Фото чеков** — Telegram-ссылки на файлы по `file_id` временные, поэтому бот пересылает фото
  в `LOG_CHAT_ID` и сохраняет в таблицу постоянную ссылку на пересланное сообщение (работает для
  каналов/супергрупп с `-100...` в ID; для обычных приватных чатов такая ссылка не открывается
  посторонними, но сохраняет файл в истории чата и остаётся кликабельной для админа бота).
- **Безопасность** — бот закрытый: любое действие (кроме `/start`) проверяет, что пользователь
  есть в таблице `users` и `active = 1`. Заблокированный (`🗑 Удалить сотрудника`) сотрудник
  теряет доступ мгновенно.

```
hr_bot/
├── main.py                  # точка входа
├── config.py                # переменные окружения
├── db/

│   └── sheets.py            # интеграция с Google Sheets (gspread)

│   └── forms.py             # FSM-состояния всех диалогов

│   ├── reply.py              # постоянные кнопки внизу экрана

├── handlers/
│   ├── common.py             # /start, /cancel, главное меню
│   ├── status.py             # модуль «Статус»
│   ├── acts.py                # модуль «Акты»
│   ├── finance.py             # модуль «Финансы»
│   └── admin.py               # админ-панель
├── utils/
│   └── formatting.py         # текстовые карточки-уведомления
├── requirements.txt
├── .env.example
└── README.md
```
